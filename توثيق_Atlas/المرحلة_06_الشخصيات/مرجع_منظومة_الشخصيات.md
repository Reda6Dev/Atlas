## 2. المخطط الهندسي القادم لمنظومة الشخصيات (Planned Engineering Architecture)

---

### أ. نموذج بيانات الشخصية (Character Data Model)
إنشاء كائن Domain جديد `Character.kt` في موديول `:domain`:
```kotlin
data class Character(
    val id: Long,
    val mangaId: Long,
    val name: String,
    val nativeName: String?,
    val role: String?, // Main, Supporting, Background
    val imageUrl: String?,
    val description: String?,
    val isFavorite: Boolean = false,
)
```

---

### ب. مخطط قاعدة البيانات (SQLDelight Schema)
إنشاء جدول جديد `characters.sq` في الموديول `:data` (`data/src/main/sqldelight/tachiyomi/data/characters.sq`):
```sql
CREATE TABLE characters (
    _id INTEGER NOT NULL PRIMARY KEY AUTOINCREMENT,
    manga_id INTEGER NOT NULL,
    name TEXT NOT NULL,
    native_name TEXT,
    role TEXT,
    image_url TEXT,
    description TEXT,
    is_favorite INTEGER AS Boolean NOT NULL DEFAULT 0,
    FOREIGN KEY (manga_id) REFERENCES mangas (_id) ON DELETE CASCADE
);
```

---

### ج. تجريد مزود بيانات الشخصيات (Character Provider Abstraction)
إنشاء واجهة `CharacterProvider` لتمكين جلب بيانات الشخصيات وصورها من مزودات متعددة (مثل AniList API, MyAnimeList, أو خادم Atlas المستقبلي) دون ربط صلب:
```kotlin
interface CharacterProvider {
    suspend fun getCharactersForManga(manga: Manga): List<Character>
}
```
